# Сетевые ресурсы SDN

Network изолирует приватный трафик, Subnet задаёт диапазон адресов, Port — один
NIC ноды. Address резервирует IP или связывает FIP с Port.
[Пример](private-network.md) · [Dataplane](dataplane.ru.md).

## Ресурсы

| Ресурс | Основные поля |
| --- | --- |
| Network | `driver_spec`, `access`; read-only `driver_state`, `is_default` |
| Subnet | `network`, неизменяемый `cidr`, `ip_range`, `dhcp`, `routers`, `dns_servers`, признаки пулов |
| Port | `node`, `index`, размещение, `target_ipv4`, `target_mac`, сервисы/политика, `owner_node`; выделенные `ipv4`, `mac`, `status` |
| Address | `kind`, размещение, необязательный `address`, `port`, `owner_port`; состояние выделения/публикации |
| SecurityGroup | Имя и описание; read-only `rules` |
| SecurityGroupRule | `security_group`, `direction`, `protocol`, необязательный `port`, `remote_ip` или `remote_group_id` |
| PortSecurityGroup | Неизменяемая привязка `port`, `security_group` |
| NetworkFunction | Пользовательские настройки DHCP/DNS в `config`; proxy управляется инсталляцией |
| ProxyService | HTTP-сервис внутри Network; [руководство](paas-networking-guide.md) |

Коллекции `/v1/network/`: `networks`, `subnets`, `ports`, `port_security_groups`,
`nfs`, `catalog/{addresses,security_groups,security_group_rules,proxy_services}`.
В манифестах используется та же иерархия под `$core.network`.

Явное размещение принимает ровно одно из `network` и `subnet`. Network должен
однозначно выбирать доступную подходящую Subnet; неоднозначность возвращает 409.
Port без селектора использует политику размещения проекта.
Address требует `kind`: `reservation` резервирует IP без Port, `floating`
может привязываться к Port. Поддерживается один FIP на Port. Подсеть, значение
адреса и kind после выделения неизменяемы.

Для `routers` и `dns_servers` Subnet значение `null` включает автоматические
настройки: при DHCP и CIDR больше двух адресов первый адрес хоста используется
как шлюз по умолчанию и DNS; иначе оба списка пусты. Явный `[]` отключает
соответствующую настройку; явный список используется и при выключенном DHCP.
Отсутствие поля в POST означает `null`; PUT сохраняет пропущенное поле, а явный
`null` возвращает автоматические настройки. Ответ содержит сохранённые списки;
поля со значением `null` опускаются.

## Создание Node и подключения

Node и NodeSet принимают шаблон основного Port в `default_network`:

| Вход | Результат |
| --- | --- |
| Поле отсутствует | Автоматическое размещение без FIP |
| `{}` | Без Port, кроме наследования flat при включённой совместимости |
| `{network: UUID}` или `{subnet: UUID}` | Port в выбранной сети/подсети |
| `{auto_floating_ip: true}` | Дефолтный SDN Port и автоматически выделенный FIP |
| `{network: UUID, auto_floating_ip: true, floating_network: UUID}` | Явная приватная сеть и Network пула FIP |

`floating_network` требует `auto_floating_ip=true`. Запрос FIP без явного
приватного селектора всегда выбирает SDN, даже если в проекте есть flat-порты.
Также принимаются `target_ipv4` и `port_security`; шаблон NodeSet не может
фиксировать IP. Node, дефолтная сеть/подсеть, Port и FIP создаются атомарно.

Дефолтная Network определяется read-only признаком `is_default=true`, создаётся
лениво вместе с DHCP-подсетью `10.128.0.0/20`. Имя не участвует в выборе.
Запись IAM Project не требуется.

`[network] legacy_flat_default=True` позволяет наследовать единственную подходящую
flat-подсеть существующих портов проекта. Boot-подсети и адресные пулы исключаются;
при нескольких подходящих подсетях возвращается 409. Если подходящей flat-подсети
нет, выбирается SDN. В конфигурации новых инсталляций параметр равен `False`;
обновление сохраняет существующую конфигурацию. Явные селекторы имеют приоритет.
Отключение совместимости не меняет существующие подключения.

Node хранит `default_network` как обычный шаблон. Обновление сохраняет запрос,
не создавая, не перемещая и не удаляя Port/FIP; они создаются только в Node insert.
NodeSet применяет шаблон к новым репликам, сохраняя подключения существующих.
Сетью реплик управляют через NodeSet. Дополнительные NIC обычной Node —
самостоятельные Port.

Селекторы сети и признаки создания отражают сохранённый шаблон. Текущие адреса
и основной Port доступны через `default_network.ipv4`, `.port`, `.floating_ip`.
Эти read-only значения вычисляются из Port/Address; после смены шаблона реальную
Network/Subnet смотрите в указанном Port. У NodeSet — `nodes[uuid].ipv4`, `.floating_ip`.
FIP возвращается строкой и отсутствует без привязки. Эти поля показывают
выделение и привязку; применение на гипервизоре отражает статус Port/Address.
Все порты ноды: `GET /v1/network/ports/?node=NODE_UUID`.

Отсоединённый Port имеет `node=null`, `index=null`. Подключение без индекса
выбирает младший свободный; индекс 0 — основной для загрузки/установки.
Индекс подключённого Port неизменяем. Отключение сохраняет IP/MAC и не меняет
индексы остальных портов. Hotplug обновляет live и persistent конфигурацию libvirt.
Удаление последнего Port не создаёт замену; для прошивки VM нужен основной Port.

## Floating pools и права

Оператор готовит Subnet с `floating_pool=true`, `placeable=false`. Она может
содержать приватные или публичные IPv4. `shared_pool=true` разрешает другим
проектам выделение адресов из этой Subnet; Network `access=public` открывает
видимость и выделение в сети. Эти признаки не настраивают внешний uplink.

Без `floating_network` выбирается доступный `default_floating_pool`, а при его
отсутствии — единственный доступный floating pool. Нет пула — 400;
неоднозначность — 409. На проект владельца допускается один дефолтный пул.
Изменение признаков пула требует `network.subnet.floating_pool`.

Для автоматического основного Port достаточно права создания Node/NodeSet.
Самостоятельный Port требует `network.port.create`, FIP — `network.address.create`.
Явный IP в чужом общем/публичном пуле дополнительно требует
`network.address.explicit_address`, публикация сети — `network.network.share`.
Эти операторские права не выдаются владельцам проектов по умолчанию.
Приватное размещение и привязки Node/Port/SG/FIP остаются в одном проекте.

## Владение и удаление

`Port.owner_node` связывает жизненный цикл Port с Node. Автоматические порты
получают владельца, самостоятельные создаются без него. PUT может снять владение
через `null` или установить `owner_node=Port.node` с правом изменения Node.
Отключение Port снимает владельца.

`Address.owner_port` аналогично управляет автоматическим FIP. Отвязка снимает
владение; PUT может снять его отдельно или установить `owner_port=Address.port`
с правом изменения Port. Ресурсами реплик управляют через NodeSet.
При самостоятельном создании оба поля владельца доступны только для чтения.

Удаление Node удаляет её собственные Port и их SG-привязки. Независимые Port
отсоединяются и сохраняются. Удаление Port удаляет его собственные FIP.
Независимые FIP сохраняются при удалении Node; прямое удаление Port блокируется,
если остались независимые FIP/привязки. Сети и SG сохраняются.

Перенос Port/FIP выполняется через отключение/отвязку, затем подключение/привязку.
Освобождённые IP/MAC доступны повторно без подтверждения удаления старым хостом.
Удаление target запускает штатную очистку при согласовании хоста. Вернувшийся
недоступный хост может отвечать за прежний адрес до удаления устаревшего состояния.
Перенос Port или FIP не сохраняет conntrack-сессии.

Статусы Address: `UNBOUND`, `IN_PROGRESS`, `ACTIVE`, `ERROR`. ACTIVE требует отчёта
назначенного хоста для текущего задания.

## Фильтрация

Без привязок SG порт пропускает трафик, если не установлен
`enforce_security_group=true`. По умолчанию он `false`; `true` закрывает оба
направления до разрешающих правил. Привязанные SG объединяют разрешения;
неразрешённый трафик запрещён, в том числе при пустой SG. SG применяются к
overlay-портам. `port_security=true` независимо включает защиту от подмены MAC/IP.

Правила поддерживают `any`, `tcp`, `udp`, `icmp`, один TCP/UDP-порт и IPv4/CIDR
в `remote_ip`. `remote_group_id` действует только на ingress, ссылается на SG
того же проекта, включая саму себя, и выбирает участников только в Network
защищаемого Port. Он несовместим с `remote_ip`.
[Лимиты remote SG](security-group-remote-access.md) действуют на сеть.

## Обновления, манифесты и миграция

Пропущенные поля верхнего уровня сохраняют текущие значения. Явные словари
и списки заменяют значение целиком; `{}` сбрасывает пользовательские настройки
NF. `Network.driver_spec` должен содержать драйвер. Read-only проекции нельзя
использовать для SQL-фильтрации и сортировки. Значения NF по умолчанию вычисляются
при компиляции; в `config` хранятся только пользовательские настройки.

[Пример манифеста](../../exordos/manifests/examples/sdn-networking.yaml) создаёт
VM с автоматическим FIP и самостоятельный Port/SG. Адаптируйте пул, образ и
исходный CIDR к инсталляции. Манифест управляет объявленными ресурсами; ссылка
сама по себе не передаёт владение. Compute и сетевые ресурсы EM создаются
в служебном проекте. Фильтры DB-агента подставляют пропущенный project ID
и ограничивают поиск; декларации должны использовать тот же проект.

Миграция `0010-network-sdn-9e41c7.py` следует за схемой master и сразу создаёт
итоговые таблицы SDN. Существующие flat-порты сохраняют UUID, IP/MAC и подключения;
отсутствующий `source` заполняется именем Subnet. Подключённые порты получают
владельца Node и стабильные индексы. Пустые сохранённые шаблоны NodeSet становятся
отсутствующими. Примените миграции до запуска обновлённого Core и используйте
совместимые сборки Core/SDK на control plane и гипервизорах.

## Транспорт метадаты

Локальный прокси определяет вызывающую ВМ по фильтру MAC/IP её Port и
передаёт Boot API запросы в Core по TCP 11015. Запросы и ответы шифруются
ChaCha20-Poly1305 существующим ключом агента обслуживающего гипервизора.
Core проверяет гипервизор, принадлежность ВМ, метод, путь, заголовки и тело;
просроченные и повторные запросы отклоняются. Перехода на открытый текст
нет. Установленные агенты сохраняют прежний зашифрованный протокол
Orch/Status и свои ключи.

Старый Seed до получения ключа использует HTTP внутри доверенной Boot-сети.
Прежний listener привязан к Boot IP на TCP 11013 и принимает трафик только
с этого интерфейса. Core определяет ноду по статическому IP Port либо MAC
активной DHCP-аренды и ограничивает доступ к чувствительным ресурсам этой
нодой. Чтение ключа отключено; обновить свой ключ можно только при
разрешённой сервером сетевой установке. Этот участок требует изоляции
Boot L2: IP и аренда не обеспечивают криптографическую аутентификацию
против другого участника Boot-сети.

Обновляйте Core и SDK согласованно и перегенерируйте SDN drop-in: прежний
listener должен сохранять Boot IP, а `proxy_endpoint` — указывать на
зашифрованный listener. Для realm с дополнительными гипервизорами Border
должен пробрасывать TCP 11015 вместо TCP 11013. Существующие ключи нод
автоматически не ротируются.

Лимит зашифрованного запроса — 2 MiB, ответа — 32 MiB (примерно 24 MiB
полезного тела). При превышении размера ответ 413 также зашифрован.
