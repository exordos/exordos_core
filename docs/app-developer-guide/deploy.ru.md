## Обзор

Установить собранный элемент в realm платформы Exordos Core можно двумя способами:

- `exordos elements install` — устанавливает элемент из репозитория или из локального файла манифеста. Используйте, когда элемент уже собран и опубликован, либо при установке из пути к манифесту.
- `exordos deploy` — собирает, публикует (опционально) и устанавливает за один шаг. Используйте, чтобы развернуть локально собранный элемент без отдельного `exordos push`.

---

## exordos elements install

`exordos elements install` **устанавливает** элемент в realm платформы Exordos Core с необходимыми зависимостями.

```bash
exordos elements install [OPTIONS] [UUID_OR_NAME_OR_PATH]
```

Ключевые опции:

| Опция | Описание |
|---|---|
| `-v, --version TEXT` | Версия устанавливаемого элемента |
| `-p, --project-id UUID` | UUID проекта, требуется только если репозиторий загрузки ещё не существует |
| `--timeout FLOAT` | Время ожидания загрузки в репозиторий и синхронизации элемента в секундах (по умолчанию: `600`) |
| `UUID_OR_NAME_OR_PATH` | UUID элемента, имя элемента в репозитории или путь к локальному файлу манифеста |

Если аргумент не указан, команда интерактивно выводит список доступных в репозитории элементов и предлагает выбрать один.

Вы можете устанавливать элементы на [публичную установку Exordos Core](../usage/public-installation.md). Или вы можете развернуть [приватную установку Exordos Core](../usage/private-installation.md) на своём оборудовании. Для разработки и тестирования вы можете использовать [установку на локальном ноутбуке](../usage/local-laptop-installation.md).

### Установка из репозитория

Для установки элемента по имени из стандартного репозитория:

```bash
exordos elements install my-element
```

Команда получает манифест элемента из репозитория, разрешает зависимости и разворачивает элемент в текущем realm.

### Установка конкретной версии

```bash
exordos elements install -v 1.2.3 my-element
```

### Установка из локального манифеста

Для установки из локального файла манифеста передайте путь к манифесту:

```bash
exordos elements install ./manifests/my-element.yaml
```

Манифест загружается в локальный репозиторий загрузки на платформе, а затем устанавливается оттуда.

### Установка по UUID

```bash
exordos elements install 11111111-2222-3333-4444-555555555555
```

## exordos deploy

`exordos deploy` **развёртывает собранный элемент в realm за один шаг**. Элемент должен быть уже собран (`exordos build`). Без `--repository` результат локальной сборки обслуживается во встроенном HTTP-сервере и устанавливается напрямую — `exordos push` не требуется. С `--repository` сборка сначала публикуется (как при `exordos push`), а затем устанавливается.

```bash
exordos deploy [OPTIONS]
```

Ключевые опции:

| Опция | Описание |
|---|---|
| `-e, --element-dir PATH` | Директория с артефактами элемента (результат `exordos build`, по умолчанию: `output/`) |
| `-t, --repository TEXT` | Имя репозитория (ключ из секции `repositories` в `~/.exordos/exordosctl.yaml`). Включает режим push: сначала опубликовать сборку в этот репозиторий, затем установить. Если не указан, используется локальный режим (без push) |
| `--element TEXT` | Имя элемента для развёртывания из inventory сборки. Если не указан и доступно несколько элементов, появляется интерактивный выбор |
| `-r, --realm TEXT` | Имя realm для развёртывания. Если не указано, используется текущий realm из конфигурации |
| `-p, --project-id UUID` | UUID проекта, требуется только если dev-репозиторий ещё не существует |
| `--dev-repo-name TEXT` | Имя локального dev-репозитория для публикации развёртываемых элементов (по умолчанию: `exordos-dev-repo`) |
| `--dev-repo-priority INTEGER` | Приоритет локального dev-репозитория, 0–4096 (по умолчанию: `4096`) |
| `-f, --force` | Принудительная публикация, даже если элемент уже существует (только для режима push) |
| `--timeout FLOAT` | Время ожидания синхронизации репозитория и установки элемента в секундах (по умолчанию: `600`) |
| `-c, --exordosctl-cfg-file TEXT` | Имя файла конфигурации exordosctl |
| `--port INTEGER` | TCP-порт для встроенного HTTP-сервера в локальном режиме (по умолчанию: `33101`) |

### Развёртывание локальной сборки (без push)

После `exordos build` развёртывайте результат сборки напрямую без публикации в удалённый репозиторий:

```bash
exordos deploy
```

Команда обслуживает директорию `output/` через временный локальный HTTP-сервер и устанавливает элемент оттуда.

### Развёртывание с публикацией

Чтобы сначала опубликовать сборку в настроенный репозиторий, а затем установить:

```bash
exordos deploy --repository my-repo
```

Репозиторий должен быть настроен в `~/.exordos/exordosctl.yaml` в секции `repositories` (см. `exordos settings repo add`).

### Развёртывание конкретного элемента

Если сборка создала несколько элементов, выберите один:

```bash
exordos deploy --element my-app
```

## Конфигурация

### Целевой realm

Обе команды развёртывают в realm Exordos Core, который в данный момент настроен в вашем окружении. Убедитесь, что у вас есть:

- Валидные учётные данные для целевого realm
- Сетевое подключение к конечной точке API realm
- Достаточные разрешения для установки элементов

### Выбор репозитория

`exordos elements install` разрешает элементы из репозиториев, зарегистрированных на платформе. Чтобы использовать пользовательский репозиторий, зарегистрируйте его с помощью `exordos settings repo add` или через API платформы перед установкой.

`exordos deploy --repository` публикует в репозиторий, определённый в `~/.exordos/exordosctl.yaml` в секции `repositories`.
