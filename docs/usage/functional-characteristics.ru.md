Exordos Core — открытая программная платформа (NoOps) для автоматизации развёртывания, управления и эксплуатации IT-инфраструктуры и корпоративного программного обеспечения. Платформа предназначена для использования в локальных, частных, публичных и гибридных средах.

## 1. Назначение и область применения

Область применения:

- Автоматизация развёртывания и управления виртуальными машинами и физическими серверами.
- Декларативное управление конфигурациями, секретами, переменными и профилями.
- Управление жизненным циклом элементов (приложений и инфраструктурных компонентов).
- Управление доступом и правами пользователей (IAM).
- Балансировка нагрузки и управление DNS.
- Развёртывание и обновление приложений в образной среде.

## 2. Функциональные модули

Платформа включает следующие функциональные модули.

### 2.1. Модуль Compute (Вычисления)

Обеспечивает создание и управление виртуальными машинами (KVM/QEMU) и физическими серверами.

- Создание, настройка и удаление виртуальных машин (Node).
- Группировка узлов в NodeSet с указанием целевого количества реплик (`replicas`).
- Образное обеспечение: вычислительные узлы создаются и обновляются из образов; при обновлении корневой диск заменяется целевым образом с сохранением прикреплённых томов и сетевых идентификаторов.
- Управление гипервизорами (Hypervisor) и пулами хранения.
- Политики размещения узлов (PlacementPolicy).

### 2.2. Модуль Storage (Хранение)

Обеспечивает создание и подключение дисковых томов (Volume) для постоянного хранения данных.

- Создание томов с указанием размера и типа.
- Поддержка нескольких дисков на узел (корневой диск + диски данных).
- Подключение и отключение томов к вычислительным узлам.

### 2.3. Модуль Network (Сеть)

Обеспечивает управление сетевыми ресурсами.

- Создание и настройка сетевых ресурсов.
- Управление сетевыми подключениями узлов.
- Поддержка маршрутизации и сетевой изоляции проектов.

### 2.4. Модуль DNS

Обеспечивает управление DNS-ресурсами через встроенный DNS-сервер на базе CoreDNS.

- Создание и управление DNS-доменами.
- Создание DNS-записей типов A, NS, SOA, TXT.
- Синхронизация доменов с внешним DNS (ecosystem DNS).

Зеркало realm добавляет `realm:<realm_uuid>` в теги каждой upstream-записи и
обновляет или удаляет только записи со своей меткой. Локальные теги `realm:`
заменяются меткой текущего realm. Записи других realm и немаркированные записи
сохраняются, в том числе при конфликте UUID.
Метка служит для reconciliation; доступ к API по-прежнему определяется IAM и
правами проекта.

Перед передачей старых записей зеркалу проверьте их происхождение и добавьте метку
realm через upstream DNS API, сохранив остальные теги. Совпадение UUID или
содержимого само по себе не подтверждает владение. Старый upstream API без
поддержки тегов принимает новые немаркированные записи, но существующие записи
не обновляются и не удаляются до обновления upstream и явного добавления метки.
Зеркало повторно проверяет неподдерживаемый фильтр тегов через час; остальные
серверные ошибки передаются как ошибки. Список записей поддерживает
`q=tags:"realm:<realm_uuid>"`; неизвестные параметры полей и значения неверного
типа возвращают HTTP 400. Имя записи `*` обозначает wildcard зоны.

### 2.5. Модуль Load Balancer (Балансировка нагрузки)

Обеспечивает балансировку нагрузки на основе nginx.

- Создание и управление балансировщиками нагрузки (LB).
- Поддержка виртуальных хостов (Vhost) с протоколами HTTP, HTTPS, TCP, UDP.
- Бэкенд-пулы с алгоритмом балансировки `roundrobin`.
- Маршрутизация на основе префиксов и L4 (raw).
- Поддержка TLS-терминации (HTTPS).

### 2.6. Модуль IAM (Управление доступом)

Обеспечивает управление пользователями, ролями и правами доступа.

- Модель «deny by default» — доступ явно предоставляется через права.
- Управление пользователями (User), организациями (Organization), проектами (Project).
- Роли (Role) и привязки прав (Permission Binding, Role Binding).
- Привязки ролей глобальные и проектно-ограниченные.
- Интроспекция токенов для проверки прав доступа.
- Поддержка wildcard-прав (`*.*.*`).
- Типы пользователей: `user`, `service`, `anon`.

### 2.7. Модуль Secrets (Секреты)

Обеспечивает хранение и управление конфиденциальными данными.

- Управление паролями (Password): автоматическая генерация (`AUTO_HEX`, `AUTO_URL_SAFE`) и ручные значения (`MANUAL`).
- Управление TLS-сертификатами (Certificate): автоматическое выпускание через ACME (Let's Encrypt) с DNS-01 проверкой через встроенный CoreDNS.
- Управление SSH-ключами и RSA-ключами.

### 2.8. Модуль Configs (Конфигурации)

Обеспечивает доставку конфигурационных данных до вычислительных узлов.

- Создание конфигурационных файлов с текстовым содержимым.
- Доставка файлов на целевые узлы с указанием пути, владельца, прав доступа.
- Автоматическое обновление конфигурации при изменении связанных значений (отслеживание ссылок).
- Действия при изменении: `no_action`, `shell` (например, перезапуск сервиса).

### 2.9. Модуль Services (Сервисы)

Обеспечивает управление системными сервисами на вычислительных узлах.

- Создание и управление systemd-сервисами на узлах и NodeSet.
- Типы сервисов: `simple`, `oneshot`, `monopoly`, `monopoly_oneshot`.
- Управление жизненным циклом: запуск, остановка, обновление.
- Зависимости между сервисами (After, Before).

### 2.10. Модуль Values Store (Хранилище переменных)

Обеспечивает управление переменными, значениями и профилями.

- Переменные (Variable) с профильной привязкой (`develop`, `small`, `medium`, `large`, `legacy`).
- Селекторные переменные с возможностью привязки значений.
- Значения (Value) — конкретные данные, привязанные к переменным.
- Профили (Profile) — наборы значений для разных масштабов развёртывания.

### 2.11. Модуль Element Manager (Управление элементами)

Обеспечивает установку, обновление и управление жизненным циклом элементов.

- Установка элементов из манифеста (YAML).
- Разрешение зависимостей между элементами (requirements).
- Импорт и экспорт ресурсов между элементами.
- Обновление элементов с сохранением состояния.
- Удаление элементов с проверкой зависимостей.
- Непрерывная сверка (reconciliation loop) декларированного и фактического состояния.

### 2.12. Модуль Marketplace (Каталог элементов)

Обеспечивает публичные и частные каталоги элементов.

- Обнаружение и установка элементов из каталогов.
- Публичные каталоги для распространения элементов.
- Частные каталоги для корпоративных элементов.

## 3. Технические характеристики экземпляра

### 3.1. Системные требования (хост для развёртывания)

| Параметр | Минимальное значение | Рекомендуемое значение |
| --- | --- | --- |
| ОС | Ubuntu 24.04 / 26.04 | Ubuntu 26.04 |
| Архитектура | x86_64 | x86_64 |
| CPU | 4 ядра | 8+ ядер |
| RAM | 8 GB | 16 GB |
| Диск (свободное место) | 50 GB | 100+ GB |
| Гипервизор | QEMU 8.2+, libvirt 10.0+ | QEMU 9.0+, libvirt 10.0+ |

### 3.2. Характеристики управляемых виртуальных машин

| Параметр | Диапазон |
| --- | --- |
| CPU на VM | от 1 до 32+ ядер |
| RAM на VM | от 512 MB до 512+ GB |
| Размер корневого диска | от 1 GB |
| Размер диска данных | от 1 GB |
| Тип узла | VM (KVM/QEMU) или HW (bare metal) |
| Максимальное количество узлов | ограничено ресурсами гипервизора |
| Максимальное количество NodeSet | ограничено ресурсами гипервизора |

### 3.3. Сетевые характеристики

| Параметр | Значение |
| --- | --- |
| Сеть платформы | `10.20.0.0/22` (по умолчанию, настраивается) |
| Протоколы HTTP API | HTTP/HTTPS |
| Аутентификация HTTP API | Bearer token (JWT) через IAM |
| SSH-доступ к VM | по публичному ключу |

### 3.4. Состав и требования к ПО хоста

| Компонент | Версия |
| --- | --- |
| QEMU | >= 8.2 |
| libvirt | >= 10.0 |
| curl (для CLI) | любая современная |
| Python (для агентов) | >= 3.10 |
| systemd | любая современная |

## 4. Функциональные возможности (полный перечень)

1. Создание, настройка и удаление виртуальных машин и физических серверов.
2. Создание NodeSet для масштабирования нагрузки с целевым количеством реплик.
3. Управление томами (Volume): создание, подключение, отключение.
4. Управление сетевыми ресурсами и подключениями.
5. Управление DNS-доменами и записями (A, NS, SOA, TXT).
6. Управление балансировщиками нагрузки (nginx-based).
7. Балансировка HTTP/HTTPS/TCP/UDP трафика.
8. Установка элементов (приложений) из манифестов с разрешением зависимостей.
9. Обновление и удаление элементов с проверкой зависимостей.
10. Импорт и экспорт ресурсов между элементами.
11. Централизованное управление конфигурационными файлами с доставкой на узлы.
12. Централизованное управление секретами: пароли, сертификаты, ключи.
13. Автоматическая генерация паролей (`AUTO_HEX`, `AUTO_URL_SAFE`).
14. Автоматическое выпускание TLS-сертификатов через ACME (Let's Encrypt) с DNS-01.
15. Управление переменными, значениями и профилями (Values Store).
16. Профили масштабирования: `develop`, `small`, `medium`, `large`, `legacy`.
17. Управление пользователями, ролями, правами доступа (IAM).
18. Модель безопасности «deny by default».
19. Привязка ролей глобальная и проектно-ограниченная.
20. Управление сервисами (systemd) на узлах: создание, запуск, остановка, обновление.
21. Непрерывная сверка (reconciliation loop) декларированного и фактического состояния.
22. Отслеживание связанных полей (links) и автоматическое обновление зависимых ресурсов.
23. Образное обеспечение вычислительных узлов с заменой корневого диска.
24. Доступ к HTTP API платформы для интеграции с внешними системами.
25. CLI для управления платформой (`exordos` CLI).
26. Обнаружение и установка элементов из публичных и частных каталогов.

## 5. API и интеграция

Платформа предоставляет HTTP REST API для управления всеми ресурсами.

| Ресурс | API Endpoint |
| --- | --- |
| MachinePool (Hypervisor) | `GET/POST /v1/compute/hypervisors/` |
| Node (VM) | `GET/POST /v1/compute/nodes/` |
| NodeSet | `GET/POST /v1/compute/sets/` |
| Volume | `GET/POST /v1/compute/volumes/` |
| Config | `GET/POST /v1/config/configs/` |
| Domain | `GET/POST /v1/dns/domains/` |
| LB | `GET/POST /v1/network/lb/` |
| Service | `GET/POST /v1/em/services/` |
| Certificate | `GET/POST /v1/secret/certificates/` |
| Password | `GET/POST /v1/secret/passwords/` |
| User | `GET/POST /v1/iam/users/` |
| Organization | `GET/POST /v1/iam/organizations/` |
| Project | `GET/POST /v1/iam/projects/` |
| Role | `GET/POST /v1/iam/roles/` |
| Permission | `GET/POST /v1/iam/permissions/` |
| Profile | `GET/POST /v1/vs/profiles/` |
| Variable | `GET/POST /v1/vs/variables/` |

Полная спецификация API доступна в документации в формате OpenAPI (Swagger).
