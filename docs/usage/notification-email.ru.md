title: Почтовые уведомления с авторизацией
---

Штатный отправитель событий SDK в Core поддерживает авторизацию Notification 2.0.
Он читает `[events] exordos_api_token` и передаёт `Authorization: Bearer ...`
при отправке события и запросе его статуса. User API сохраняет события через
асинхронный клиент SDK, а `ec-gservice` отдельно доставляет их из очереди.

Чтобы включить интеграцию, установите дополнительный элемент Core:

```bash
exordos elements install core_notification_email
```

Его `requirements` подтягивают `notification_email` из репозитория Notification.
Этот элемент предоставляет общий SMTP-транспорт и зависит от базового сервиса
Notification и mailaas. Элемент Core владеет типами событий регистрации и сброса
пароля, шаблонами писем, служебным пользователем, правами на почтовые события
и автоматически обновляемым IAM-токеном. Он доставляет в Core следующие файлы:

- `event_type_mapping.yaml`: соответствие событий регистрации и сброса пароля
  типам событий Notification.
- `exordos_core.d/90-notification-events.conf`: включает асинхронный клиент
  и задаёт адрес Notification и проект.
- `exordos_core.d/91-notification-token.conf`: задаёт управляемый токен
  отправителя; права файла — `0600`.

Конфиги ссылаются через импорт на ресурс `core_set`, экспортируемый Core.
Так интеграция использует набор узлов конкретной установки без фиксированного UUID.
Перед установкой дополнительного email-элемента обновите базовый элемент Core,
чтобы зарегистрировать этот экспорт.

Пути указаны относительно `/etc/exordos_core`. И `ec-user-api`, и `ec-gservice`
загружают каталог конфигурации через `--config-dir`. При изменении токена агент
конфигурации заменяет его файл и перезапускает только `ec-gservice`.
Перезапущенный клиент SDK загружает новый токен.

Подготовьте и проверьте токен отправителя до включения обязательной авторизации
в Notification. Не записывайте статический токен в базовый конфиг Core и
не создавайте ещё одну служебную учётную запись для того же отправителя.
Другим отправителям событий нужны собственные учётные данные IAM и права
на соответствующие типы событий.

Для новой установки установите `core_notification_email` и конфигурацию
Notification для вашей инсталляции. До проверки писем задайте адрес noreply.
Общий транспорт не содержит типов событий, шаблонов и конфигурации отправителя
Core; остальные приложения поставляют собственные элементы интеграции.
При переходе с объединённого элемента сначала проверьте перенос владения
ресурсами и импортов с сохранением данных. Не удаляйте действующие SMTP-ресурсы.

Элемент требует `notification_email` версии
[2.0.1](https://github.com/exordos/exordos_notification/releases/tag/2.0.1)
или новее. Первоначальная версия 2.0.0 ещё владеет ресурсами Core. До установки
этого элемента Core зарегистрируйте новую версию транспорта в репозитории
инсталляции. Минимальная версия зависимости исключает старую объединённую схему.

После настройки проверьте, что настоящее событие регистрации выходит из очереди
Core, проходит отправку и запрос статуса с авторизацией и доставляется в нужный
почтовый ящик. Также проверьте, что обновление токена сохраняет доставку
без перезапуска User API. Принятие HTTP-запроса само по себе не подтверждает
доставку письма в почтовый ящик.
